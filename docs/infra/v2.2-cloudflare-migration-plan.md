# V2.2 Infrastructure & Migration Plan: Cloudflare Pages + D1 + Cloudinary

This document outlines the 100% card-free migration plan from GitHub Pages to a dynamic stack for V2.2, supporting panel-authored blogs and case studies.

## 1. Cloudflare Pages + Vite Build
- **Setup:** The existing React 19 + Vite SPA will deploy to Cloudflare Pages identically to GitHub Pages. The build command remains `npm run build`, targeting the `dist/` directory.
- **Integration:** The GitHub repo will be wired directly to Cloudflare Pages. Cloudflare will automatically build and deploy the `dist/` folder on commits to `main`.
- **Cost/Card:** 100% Free. No credit card required.

## 2. D1 Database (SQLite)
- **Role:** D1 will serve as the CMS database, holding metadata and markdown bodies for blogs and case studies.
- **Schema:** We will define a `schema.sql` in the repo containing `blog_posts` and `case_studies` tables.
- **Hookup:** The database will be bound to the Pages project via `wrangler.toml`.
- **Cost/Card:** 100% Free (5M reads/day, 5GB storage). No credit card required.

## 3. Cloudinary (Media Storage)
- **Role:** Cloudinary will store images and media for blogs/case studies.
- **Upload Path:** The Admin panel will request an upload signature from a Cloudflare Pages Function. The client then uploads the image directly to Cloudinary using this signature.
- **Security:** The `CLOUDINARY_API_SECRET` is stored securely as a Cloudflare Pages Secret. It is **never** exposed to the client.
- **Cost/Card:** 100% Free (25 credits/month = ~25GB storage/bandwidth). **NO credit card required for signup.**

## 4. Admin Auth via Pages Functions Middleware
- **Role:** Protect the `/admin` UI route and the `/api/admin/*` API routes without relying on Cloudflare Zero Trust (which requires a credit card).
- **Setup:** A Cloudflare Pages Function middleware (`functions/api/admin/_middleware.ts`) will intercept requests to `/api/admin/*` and require an `Authorization` header holding a hashed password, validated against a `ADMIN_PASSWORD_HASH` Cloudflare Secret (mirroring our current V1 setup).

## 5. API Surface (Pages Functions)
- **Role:** Serverless API for CRUD operations and media upload signatures.
- **Implementation:** We will add a `functions/api/admin/` directory containing handlers for creating, reading, updating, and deleting blog/case study rows in D1, and generating Cloudinary upload signatures.
- **Security:** The middleware ensures these functions only execute for authorized requests.

## 6. Deploy Pipeline & CI
- **Current CI:** The existing GitHub Actions workflows (visual baselines, performance budgets, tests, oxlint) remain unchanged.
- **Deploy:** We will configure Cloudflare Pages to build on push. We can also integrate a GitHub Action (`cloudflare/pages-action`) to give GitHub CI explicit control over deployments.

## 7. DNS & Custom Domain
- **Setup:** The custom domain will be managed via Cloudflare DNS and pointed to the new Cloudflare Pages project.
- **Fallback:** The existing GitHub Pages deployment (`kuldeeplodha.github.io/kuldeep-portfolio`) will remain active indefinitely as a secondary mirror.

## 8. Rollback Strategy
- **Isolation:** Because the Vite build produces a purely static artifact, the core site remains perfectly hostable on GitHub Pages.
- **Fallback:** If the Cloudflare migration encounters issues, we simply flip the DNS records back to GitHub Pages. Read-only content remains fully functional.

## 🛠️ Execution Checklist

### 👤 KULDEEP (Human Setup — Do this first)
*Note: ALL steps below are 100% free. **NO CREDIT CARD IS REQUIRED ANYWHERE.***

1. **Create Cloudflare Account:** Sign up for a free Cloudflare account.
2. **Create Cloudinary Account:** Sign up for a free Cloudinary account.
3. **Create D1 Database:** In the Cloudflare dashboard, go to D1 and create a database (e.g., `portfolio-cms`).
4. **Connect GitHub Repo to Pages:** Go to Pages, create a new project, connect your GitHub account, select the `kuldeep-portfolio` repo, and set the build command to `npm run build` and output directory to `dist`.
5. **Add Environment Secrets to Cloudflare Pages:**
   - `ADMIN_PASSWORD_HASH`: Your SHA-256 hashed admin password.
   - `CLOUDINARY_API_KEY` & `CLOUDINARY_API_SECRET`: From your Cloudinary dashboard.
6. **DNS Update:** Point your custom domain to Cloudflare Pages (you can do this last).

### 🤖 AGENTS (Automated Work — We will do this)
1. **Wrangler Config:** Add `wrangler.toml` binding the D1 database to the Pages project.
2. **Schema Definition:** Write and commit `schema.sql` for D1.
3. **API Functions:** Implement `functions/api/admin/*` for D1 CRUD and Cloudinary upload signature generation.
4. **Auth Middleware:** Implement `functions/api/admin/_middleware.ts` to secure the API.
5. **Admin UI:** Build out the CMS interfaces in `AdminPage` for blogs and case studies.
