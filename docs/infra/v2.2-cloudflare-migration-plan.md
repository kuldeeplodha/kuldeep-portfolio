# V2.2 Infrastructure & Migration Plan: Cloudflare Pages + D1 + R2

This document outlines the migration plan from GitHub Pages to the Cloudflare stack for V2.2 to support panel-authored blogs and case studies.

## 1. Cloudflare Pages + Vite Build
- **Setup:** The existing React 19 + Vite SPA will deploy to Cloudflare Pages identically to GitHub Pages. The build command remains `npm run build`, targeting the `dist/` directory.
- **Integration:** The GitHub repo will be wired directly to Cloudflare Pages. Cloudflare will automatically build and deploy the `dist/` folder on commits to `main`.

## 2. D1 Database (SQLite)
- **Role:** D1 will serve as the CMS database, holding metadata and markdown bodies for blogs and case studies.
- **Schema:** We will define a `schema.sql` in the repo containing `blog_posts` and `case_studies` tables.
- **Hookup:** The database will be bound to the Pages project via `wrangler.toml`.

## 3. R2 Bucket (Media Storage)
- **Role:** R2 will store images and media for blogs/case studies.
- **Upload Path:** We will use Cloudflare Pages Functions to expose an upload endpoint. The Admin panel will POST media to this function, which streams it into R2. R2 will be bound to the Pages project in `wrangler.toml`.
- **⚠️ CRITICAL FLAG:** Enabling R2 **requires a credit card or PayPal** on file for verification. While it offers a generous free tier (10 GB storage, zero egress fees), Cloudflare enforces the payment method requirement to prevent abuse.

## 4. Admin Auth via Cloudflare Access (Zero Trust)
- **Role:** Instead of building a custom JWT auth flow, we will use Cloudflare Access (free for up to 50 users) to protect the `/admin` UI route and the `/api/admin/*` API routes.
- **Setup:** Cloudflare Access will intercept requests to these paths and prompt for authentication (e.g., email OTP). Only Kuldeep's email will be allowed.

## 5. API Surface (Pages Functions)
- **Role:** Serverless API for CRUD operations and media uploads.
- **Implementation:** We will add a `functions/api/admin/` directory. This will contain handlers for creating, reading, updating, and deleting blog/case study rows in D1, and for handling R2 media uploads.
- **Security:** Because Cloudflare Access sits in front of the `/api/admin/` routes, the Functions can inherently trust that incoming requests are authorized.

## 6. Deploy Pipeline & CI
- **Current CI:** The existing GitHub Actions workflows (visual baselines, performance budgets, tests, oxlint) will remain unchanged. They will run on GitHub Actions.
- **Deploy:** We will configure Cloudflare Pages to build on push. We can also integrate a GitHub Action (`cloudflare/pages-action`) to give GitHub CI explicit control over when deployments happen (e.g., only after QA passes).

## 7. DNS & Custom Domain
- **Setup:** The custom domain will be managed via Cloudflare DNS and pointed to the new Cloudflare Pages project.
- **Fallback:** The existing GitHub Pages deployment (`kuldeeplodha.github.io/kuldeep-portfolio`) will remain active indefinitely as a secondary mirror.

## 8. Rollback Strategy
- **Isolation:** Because the Vite build produces a purely static artifact, the core site remains perfectly hostable on GitHub Pages.
- **Fallback:** If the Cloudflare migration encounters issues, we simply flip the DNS records back to GitHub Pages. Read-only content remains fully functional.

## 🛠️ Execution Checklist

### 👤 KULDEEP (Human Setup — Do this first)
1. **Create Cloudflare Account:** Sign up for a free Cloudflare account.
2. **Add Payment Method (Required for R2):** Add a credit card or PayPal. *Note: R2 is free up to 10 GB storage and has no egress fees, but Cloudflare requires a card on file to activate the service.*
3. **Enable R2 & Create Bucket:** Go to R2, enable it, and create a bucket (e.g., `portfolio-media`).
4. **Create D1 Database:** Go to D1, create a database (e.g., `portfolio-cms`).
5. **Connect GitHub Repo to Pages:** Go to Pages, create a new project, connect your GitHub account, select the `kuldeep-portfolio` repo, and set the build command to `npm run build` and output directory to `dist`.
6. **Set up Cloudflare Access:** Go to Zero Trust, create an application protecting the paths `/admin` and `/api/admin/*`, and configure a policy allowing only your email address via OTP.
7. **DNS Update:** Point your custom domain to Cloudflare Pages (you can do this last).

### 🤖 AGENTS (Automated Work — We will do this)
1. **Wrangler Config:** Add `wrangler.toml` binding the D1 database and R2 bucket to the Pages project.
2. **Schema Definition:** Write and commit `schema.sql` for D1.
3. **API Functions:** Implement `functions/api/admin/*` for D1 CRUD and R2 uploads.
4. **Admin UI:** Build out the CMS interfaces in `AdminPage` for blogs and case studies.
5. **CI Integration:** Update GitHub Actions if necessary to handle the Wrangler deployments or coordinate with Cloudflare's auto-builder.
